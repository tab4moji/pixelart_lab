# 複数形状の Z バッファ合成

大文字キー(Shift+形状キー)で足した形状を、画素ごとの深度で合成して表示する。
小文字キーの単独表示は従来のコードのまま(見た目は変わらない)。

## 方針

- 単独表示(形状が1つ): 従来の描画をそのまま使う。立方体系はポリゴン塗り、他はレイキャスト。
- 複数表示(形状が2つ以上): すべての形状を「画素ごとの光線サンプリング」に統一し、Zバッファで合成する。

ポリゴン塗りは画素ごとの深度を持たないため、立方体系も合成のときだけ光線との交点で扱う。

## サンプラの形

形状ごとに次の形の関数(sampler)を作る。

```
sampler(px, py, x_pos, up) -> (深度 t, 色, 面ID) または None
```

- 深度 t はビュー空間の手前方向の値。大きいほどカメラに近い。
- 面IDは立方体系の面の番号。他の形状は 0。
- 形状ごとの sample_pixel()(cylinder_cast など)に view と形状パラメータを束縛して作る(samplers.py)。

## Zバッファ

全形状のサンプラを全画素に当て、画素ごとに深度 t が最大の結果だけを残す。
形状は(0, 0, 0)を中心に置いたままなので、重なる所は交差した姿で見える。

## 立方体系の交点

面は外向き法線 n と平面定数 d (n・P <= d) で表す。光線 P = q + t e について次のとおり。

```
slack = d - n・q,  rate = n・e
rate > 0: t <= slack / rate  (カメラ側の面 -> 出口の候補)
rate < 0: t >= slack / rate  (入口の候補)
rate = 0: slack >= 0 のときだけ内側
```

- 出口の最小値 t_exit が表面、入口の最大値 t_enter <= t_exit なら交差する。
- 法線は符号と比しか使わないので正規化は不要(wedge の (1,0,1) などでも動く)。
- q は x, 上 の線形関数なので、n・q の係数と n・e はフレームごとに前計算する。

## 輪郭線

単独表示では立方体系の面に白い輪郭線(色 7)を引いていた。合成でも同じ見た目にするため、
画素の隣との関係から輪郭を決める。

- 隣が背景、または輪郭対象でない形状: こちらの画素を輪郭にする。
- 隣が別の面や別の立方体系の形状: 識別子(形状番号, 面ID)の大きい側だけを輪郭にする。
- 線幅を1画素に保つため、境界を挟む2画素のうち片側だけを輪郭にする。

単独のポリゴン描画の輪郭と、画素の位置が1画素ずれることがある。

## 重複の扱い

同じ形状は何度足しても1つ(選択リストに重複を入れない)。

## 速度

サンドボックスでの実測(1フレームの合成)は次のとおり。実機では変わる。

| 形状 | 時間 |
| --- | --- |
| cube 1つ | 約 5ms |
| cube + cylinder | 約 7ms |
| 7形状すべて | 約 24ms |

30fps の枠は約 33ms。7形状すべてで実機が遅いと、フレームが落ちる可能性がある。

## 検証メモ

- 立方体系の交点の深度は、面ごとのポリゴンとの交点の総当たりと 1200 サンプルで一致した。
- 立方体系のシルエットは、投影した面を塗った画像と比べてはみ出し 0 画素だった。
- 全7形状の合成は、各形状を独立に評価した結果の深度最大と一致した。
